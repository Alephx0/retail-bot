# Account fingerprint profiles and testing

In **Accounts**, choose **Fingerprint & test**, or expand **Fingerprint profile**
when creating or editing an account. Each control offers **Use global** and an
explicit override. Global values come from Settings. Changes apply to newly
opened browsers. **Use global for all options** resets control overrides and
extension selection; saved generated presets remain available.

## Generated fingerprint tab

The **Generated fingerprint** tab probes the selected browser locally and shows
the account's repeatable CPU, memory, screen, scaling, GPU, font and rendering
presets. Its seed is saved when a new account is created. Existing accounts retain
their seed. Refresh the preview after changing controls or presets.

Every value generated by this preset generator has a corresponding choice:
CPU core count, reported memory, screen/scaling combination, GPU identity, font
set, canvas variation, WebGL variation and WebGPU capability policy. Viewport
dimensions derive from the selected screen with room for browser chrome.
Timezone and browser identity are selected on the Controls tab. These choices
apply when their corresponding surface toggle is on.

CPU and memory cannot exceed what the browser reports. GPU alternatives stay in
the detected desktop GPU family; unknown or mobile GPUs keep their real identity.
Font sets contain only installed fonts and restrict explicit enumeration, without
changing text rendering. Browser version, OS, graphics capabilities and audio
output remain native. This is a constrained preset editor, not arbitrary hardware
emulation or a guarantee that every third-party detector accepts a combination.
Presets are checked on preview and again before browser launch. Invalid choices
stop launch with an explanation.

Use **Vary GPU** to select an automatically generated GPU alias, standard WebGL
color variation and compatible WebGPU capabilities. The latest repair measured
0.20 Low with all eight surface toggles and actual GPU variation active in both
modes, meeting the user's revised acceptance target. WebGL variation now changes interpolated colors
during rendering; pixel reads and copies agree on the resulting framebuffer.
Automatic GPU generation selects a different family model when supported.

Use **Preserve actual GPU** to keep the real renderer, disable WebGL pixel
variation and retain native WebGPU capabilities. It does not change surface toggles
or the other presets. In the recorded tests this measured 0.20 Low in both modes;
it has not achieved 0.10 and does not preserve GPU perturbation. Existing accounts
keep their choices until you apply and save this preset. Aliasing a GPU model within
a family does not reproduce that model's rendering; the model/PCI pair is checked, but this does not establish full GPU emulation. See the [measurement report](fingerprint-profile-validation.md)
for the controlled comparisons and remaining limitations.

The experimental fingerprint-suite implementation generates its own complete
profile. Its custom surface and preset controls are inactive. Saved custom
presets are retained for switching back to JavaScript or Native Chromium.

## Implementations and browser identities

| Behavior | JavaScript compatibility | Native Chromium |
| --- | --- | --- |
| Application | Installed Chrome, Edge, Brave, Opera, or bundled Chromium | Dedicated pinned Chromium fork |
| Graphics changes | JavaScript drawing/API transformations with worker initialization | Browser engine changes configured at process launch |
| CPU/memory | JavaScript accessors constrained by actual hardware | Native engine switches |
| Font enumeration | Filters native local-font results; rendering preserved | Same enumeration filter; rendering preserved |
| Screen/scaling, US timezone and proxy matching | Browser context settings | Browser context settings and native timezone switch |
| WebGPU limits | Native or compatible policy | Native engine capabilities |
| Audio | Repairs missing metadata; preserves valid native values | Same policy |
| Workers | Graphics profiles initialize worker realms automatically | Engine graphics/CPU changes propagate automatically |

The application icon is incidental. Native mode uses a different engine build,
not merely a different window style. All five font/navigator/screen/location/
timezone controls are available in both modes. See the [native backend notes](native-fingerprint-backend.md)
for installation and browser-specific tradeoffs.

Choose a browser identity globally in **Settings > Browser**, or override it for
an account. Edge, Brave and Opera launch the real installed application, preserving
its native brand, client hints and version. Optional executable paths are global.
These identities require JavaScript compatibility mode; the dedicated native fork
is Chromium with Chrome identity. Selecting an incompatible combination reports
an error. This avoids claiming to be an engine that is not running.

## Normal and incognito sessions

**Launch in incognito** defaults to On to preserve existing behavior. Set it Off
globally or per account for a persistent normal profile. Each account/backend/
identity combination has a separate directory under the application's data folder
at `browser-profiles/`. Chromium manages that browser data separately from the
application's encrypted session records. Switching back to incognito does not
erase a normal profile. Managed normal profiles and extensions are unavailable
when attaching to an external CDP browser.

A saved app session is imported on the first normal-profile launch. Subsequent
launches retain the normal profile's current cookies and site data instead of
overwriting newer browser state with an older saved app session.

## Extensions and chrome.runtime

Use **Settings > Browser > Manage extensions** to install a curated extension or
register an unpacked extension folder. The catalog includes Rakuten Cash Back,
uBlock Origin Lite, Google Translate and Google Docs Offline. Catalog installation
downloads the actual package from Google's update service, verifies its CRX3
signature against the publisher's fixed extension ID, validates archive paths and
retains the publisher key. Extensions are executable third-party code with their
own requested permissions. They are not automatically updated by this installer.

Select global extensions, or choose an account-specific list (including an empty
list). With random assignment enabled, new accounts receive a saved selection of
one to three eligible registered extensions. The choice stays stable between
launches. Manually added extensions can opt out of random assignment. Removing
an extension clears its references; persistent profiles unload it on next launch.
Selected extensions are permitted in incognito as well as normal sessions.

Managed browsers also load a bundled runtime bridge with no permissions, content
scripts, background scripts or external message handlers. Its
`externally_connectable` declaration makes Chromium expose its **real**
`chrome.runtime` web messaging APIs on HTTP(S) pages. It does not manufacture
extension-context properties such as `chrome.runtime.id`. Chrome does not expose
the same runtime surface to every ordinary webpage simply because it is headed;
the [Chrome messaging documentation](https://developer.chrome.com/docs/extensions/develop/concepts/messaging#send-messages-from-web-pages)
describes the extension-to-webpage relationship.

## Test browsers and account actions

Account rows have **Open**, **Fingerprint & test**, and **More**. More contains
linked profiles, account editing and deletion. Open focuses an existing account
browser or launches one if it has closed. Closing the process clears the active
session automatically. There is no Close Test button.

**Save & test** saves the editor and opens a separate visible test browser with
the account's seed, proxy, incognito choice and extensions. It does not restore
or save retailer sign-in state or run retailer sign-in automation. Normal-mode
tests use a temporary profile instead of the account's persistent directory.
Testing the same account again replaces its previous test browser. At most five
account test browsers can be open. Account deletion and app shutdown close them.

**Test websites** manages shared starting websites. CreepJS and Google are initial
examples. Add, edit or delete up to 20 websites; each opens in its own tab. An empty
list opens a blank tab. URLs must be HTTP(S) without embedded credentials.

The [measurement report](fingerprint-profile-validation.md) records the detector
results, configuration differences and the accepted 0.20 Low bot score.
