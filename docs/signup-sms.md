# Signup phone verification and passkey prompts

Settings > Browser > Advanced browser options has **Block passkey prompts in account browsers**, enabled by default. It applies to newly opened app account contexts. Public-key credential requests are declined before the page can open Windows' authenticator dialog; password and code authentication remain available. This does not change Windows settings or other personal browser windows. A passkey-only login requires disabling this option and reopening its browser. Optional retailer passkey offers with an unambiguous Skip/Not now control are declined during signup.

Tools > Verification contains **Signup SMS verification** connections. Add an SMSPool key, a per-verification USD price cap and a bounded wait time. Keys stay in the encrypted vault and are redacted from dashboard responses. **Test connection** checks balance without buying a number. The requested default cap is **$0.50**.

Choose the connection under **Phone verification** in New account, or **Signup SMS provider** in the account's connection and verification details. A supplied mobile number takes priority; it must use international format and match the selected region. A purchased number is used only if the form actually requests a mobile number and no number was provided. SMSPool is not used to replace the number on an existing account's verification challenge.

Amazon's mobile signup field may have `name="email"`. Classification uses telephone type, autocomplete and the visible label before the misleading name. It never fills that control with the saved email. The observed phone-and-name layout is supported, including its country selector, a later SMS code and a separate password step. Only present, recognized fields receive the corresponding saved values. OTP telephone inputs are classified as code fields, not new phone-number fields. Locked conflicting values and genuinely ambiguous controls stop the affected stage.

Each signup owns one encrypted SMS order record. The request includes `max_price`, quantity one and cheapest pricing. The purchase intent is durable before the request; a timeout, interruption, unexpected price or uncertain outcome cannot trigger another purchase automatically. Codes are polled using that account's order ID, never a shared latest-message lookup. Codes are not stored in logs or the order record. Submission intent is recorded before clicking Verify. SMS and email challenges have separate routing and submission flags. Completed phone-only registrations retain the phone login identifier separately from the provided contact email.

SMSPool numbers in this integration are one-time verification numbers, not permanent account recovery numbers. Review unused or uncertain orders in SMSPool. No replacement or resend purchase is made automatically. Stock and retailer acceptance are not guaranteed by a successful connection test or a price quote.

Primary provider references: [SMSPool API guide](https://www.smspool.net/article/how-to-use-the-smspool-api-0dd6eadf4c) and [official Postman collection](https://api.smspool.net/resources/postman.json). The adapter uses `service/retrieve_all`, `request/balance`, `purchase/sms` and `sms/check`; API keys travel in POST bodies over verified HTTPS. The live catalog currently groups Amazon under “Amazon / Amazon Web Services”; its service ID is discovered rather than hard-coded.
